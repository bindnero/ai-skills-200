# Contributing

Thanks for helping improve this collection. It is 205 skills, so quality matters more than volume — a small number of excellent skills beats a large number of mediocre ones.

## The contract (validator-enforced)

Every skill is a folder `skills/<category>/<name>/` containing exactly one file `SKILL.md`:

- **Frontmatter has exactly two keys** — `name` and `description`. No extras.
- **`name` matches the folder name**, lowercase-hyphenated.
- **`description`** is third person, at least 60 chars, front-loads literal trigger keywords, and contains a trigger clause (`Use when` / `Use before` / `Use after` / `Use for` / `Use at`).
- **Body 70-130 lines** with all four sections, in order: `## Instructions`, `## Patterns`, `## Checklist`, `## Anti-patterns`.
- **A `**Do not use when:**` line** naming the adjacent skill that owns the neighbouring case.
- **No duplicate names or descriptions** across the whole repo.

Run `npm run check` before you push. It runs `validate` then `catalog`; CI enforces it on every PR.

## Adding a skill

1. Pick the category and read one or two existing skills in it — match their structure and depth.
2. `mkdir -p skills/<category>/<name>` then write `SKILL.md`.
3. Add the name to its category chapter in `scripts/docs.mjs` (`META.covers`) so it appears grouped in the docs.
4. `npm run check && npm run docs`.
5. Open a PR.

Read [docs/11-authoring.md](docs/11-authoring.md) first — it covers writing descriptions that actually trigger and splitting long content into `references/`.

## Editing an existing skill

- Change the `SKILL.md`, not the generated files. `CATALOG.md`, `catalog.json`, and `docs/02..09` are generated by `npm run catalog` / `npm run docs` — edits to them are overwritten.
- If you change a skill's `name`, rename its folder to match (the validator will fail otherwise).
- If you rename a skill, note it in the PR description so install commands in issues stay accurate.

## Local testing

```bash
npm run check                             # validate + regenerate the catalog
npm run list                              # browse all skills
node scripts/install.mjs --search "your topic"
node scripts/install.mjs --skill <name> -t agents --link   # live-edit in your tool
npm run docs                              # regenerate per-category chapters
```

Restart your tool after installing — every tool indexes skills at launch.

## Content rules

- Be correct and current. Prefer the pattern that is right by default; say when to depart from it.
- Real code in Patterns. No `...rest`, no `TODO`, no invented APIs.
- Every Anti-pattern names the failure, why it fails, and the fix.
- No duplicate content across skills — point to the sibling that owns it.
- No emoji. Address the agent that will execute the work, not a human persona.

## Commit and PR style

Commit messages: short imperative subject, explain the why in the body. PRs should say what skill(s) changed, why, and confirm `npm run check` passes. If you fixed a real install or tooling bug, mention the reproduction.
