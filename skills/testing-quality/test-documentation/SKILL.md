# Test Documentation

**Use when:** a new engineer cannot answer "what is covered, how do I run it, and who owns it" from the code, or when a service changes hands and the tests become unmaintained.
**Do not use when:** the suite is small and self-evident — a 40-test pure-function module needs no catalog; or when you need to add tests rather than describe them.

## Instructions

1. Write `TESTING.md` next to the tests, covering commands, environment prerequisites, layer definitions, data rules, and the escalation path for a red build. Keep it under 200 lines.
2. Generate the catalog from the suite rather than maintaining it by hand. Use `vitest list` to enumerate every test file and name, and commit the output so drift shows up as a diff.
3. Map each test file to the layer (unit, integration, contract, E2E, load) and to the source file it covers, so a reviewer can see the gap map without reading every spec.
4. Record ownership per directory in a machine-readable file — `CODEOWNERS` or a `TEST_OWNERS` map — and enforce it through review rather than documentation alone.
5. Document the exact commands a new engineer needs: install prerequisites, start dependencies, run one file, run one test by name, run with a debugger, and reproduce a CI failure with a seed.
6. Write the rules that are not obvious from the code: seeds to use, whether tests may run in parallel, what must never be mocked, and which suites are quarantined with an expiry date.
7. State known gaps explicitly. A "Not covered" section listing untested auth paths is more useful than silence, and it is the input to the next planning session.
8. Add a first-failure triage section: how to read a Vitest or Playwright failure, where traces land, and the flake policy including when quarantine is allowed.
9. Version the documentation with the suite and require it in review when a layer, runner, or seeding strategy changes.
10. Keep it short and current — delete stale sections rather than appending. A long out-of-date doc is worse than no doc.

## Patterns

Generate the catalog from the runner instead of maintaining it by hand:

```bash
# scripts/generate-test-catalog.ts
import { execFileSync } from 'node:child_process';
import { writeFileSync } from 'node:fs';

const raw = execFileSync('npx', ['vitest', 'list', '--filesOnly'], { encoding: 'utf8' });

const layer = (file: string) =>
  /^test\/integration\//.test(file) ? 'integration'
  : /^e2e\//.test(file) ? 'e2e'
  : /^contract\//.test(file) ? 'contract'
  : 'unit';

const rows = raw
  .split('\n')
  .map((l) => l.trim())
  .filter(Boolean)
  .map((file) => {
    const source = file
      .replace(/^test\/integration\//, 'src/')
      .replace(/^e2e\//, 'e2e/')
      .replace(/\.test\.(ts|tsx)$/, '')
      .replace(/\.spec\.(ts|tsx)$/, '');
    return `| \`${file}\` | ${layer(file)} | \`${source}\` |`;
  });

writeFileSync(
  'docs/test-catalog.md',
  [
    '<!-- Generated by scripts/generate-test-catalog.ts. Do not edit by hand. -->',
    '| Test file | Layer | Covers |',
    '| --- | --- | --- |',
    ...rows,
    '',
  ].join('\n'),
);
```

Runnable documentation that a new engineer can paste:

````markdown
# Testing guide — orders service

## Prerequisites

- Node 22, Docker (testcontainers needs it)
- `cp .env.test.example .env.test` — `DATABASE_URL` is overwritten per worker, do not hand-edit it

## Commands

| Task | Command |
| --- | --- |
| All unit tests | `npm run test:unit` |
| One file | `npx vitest run src/orders/price.test.ts` |
| One test by name | `npx vitest run -t "applies two stacked discounts"` |
| Integration (real Postgres) | `npm run test:integration` |
| E2E shard | `npx playwright test --shard=1/4` |
| Reproduce a CI flake | `SEED=20260902 npx playwright test e2e/cart.spec.ts --repeat-each=20` |
| Open the HTML report | `npx playwright show-report` |

## Rules

1. Never mock `pg` or `knex`. Use the real database; see `test-data-management`.
2. Every random fixture must use `fakerForFile(__filename)` so the seed is reproducible.
3. Integration tests may run in parallel — each worker owns `test_w$VITEST_WORKER_ID`.
4. E2E specs select by role/name. `data-testid` only for canvas or non-semantic regions.
5. Quarantining requires an owner, a ticket, and an expiry date in the spec header.

## Triage

- Vitest: assertion diff first, then check seed and worker id in the log header.
- Playwright: `npx playwright show-trace test-results/<test>/trace.zip`.
- Flaky gate: `node scripts/flake-gate.ts`. Quarantine only after root cause is recorded.

## Known gaps

- `PATCH /orders/:id` — no authorization test for the `auditor` role.
- Tax rounding for multi-currency — no property test.
````

```bash
npx vitest list --filesOnly | wc -l          # how many test files exist
npm run test -- --changed                     # only tests related to the diff
npm run lint:test-docs                        # fails if docs/test-catalog.md is stale
```

## Checklist

- [ ] `TESTING.md` exists, is under 200 lines, and lists prerequisites and exact commands
- [ ] Catalog is generated from the runner and committed, never hand-maintained
- [ ] Every test file maps to a layer and a source file
- [ ] Ownership encoded in `CODEOWNERS` and enforced by branch protection
- [ ] Seeding, parallelism, and mocking rules documented explicitly
- [ ] Known gaps listed by name, not omitted
- [ ] Triage section explains reading failures, locating traces, and the flake policy
- [ ] CI fails when the committed catalog is stale

## Anti-patterns

**Hand-maintained test list.** It is stale within two sprints and therefore actively misleading. Fix: generate it with `vitest list --filesOnly` and fail CI on drift.

**A 900-line testing wiki.** Nobody reads it, and the one command people need is buried. Fix: keep TESTING.md short and link to deeper design docs.

**Documenting only the happy command path.** A new engineer can run `npm test` and still be blocked by an undocumented container, seed, or flake reproduction. Fix: document prerequisites, seeds, trace locations, and per-layer commands.

**No ownership.** Nobody is responsible for a stale suite, so it silently stops running in CI after a dependency upgrade. Fix: CODEOWNERS on test directories with review required.
