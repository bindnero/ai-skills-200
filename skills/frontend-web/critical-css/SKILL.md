# Critical CSS

**Use when:** First Contentful Paint is delayed by stylesheets, the Network panel shows `@import` chains or several render-blocking CSS files, or one large global CSS bundle delays first paint.
**Do not use when:** the delay comes from JavaScript or images — use `bundle-size-triage` and `image-optimization`; for avoiding `@apply` bloat in Tailwind use `tailwind-architecture`.

## Instructions

1. Establish the baseline first: record FCP and LCP in Lighthouse with a CPU and network throttle, and list every render-blocking resource in the Network panel.
2. Find the true critical CSS with a real render: use DevTools "Coverage" and record the CSS rules used during first paint, or run an extractor (Beasties/critters) against the production URL.
3. Inline the extracted CSS in a `<style>` in `<head>`. Keep it under roughly 14KB compressed so the HTML response is not itself delayed.
4. Load the full stylesheet without blocking render: `rel="preload" as="style"` with an `onload` swap, plus a `<noscript>` fallback.
5. Remove every `@import` from the critical path. Each one is a serialised request after the CSS file is parsed; inline the imported sheet or add it to the bundle.
6. Split per route. Shipping every page's CSS on every route wastes bytes; generate a critical file per template and load route CSS with the route chunk.
7. Do not hand-maintain the inlined block. Generate it in the build and add a CI check that regenerating produces no diff, or the file silently rots.
8. Supplement with `content-visibility: auto` plus `contain-intrinsic-size` on long pages so off-screen sections are not styled or laid out during first paint.
9. Watch for regressions in other metrics: excessive inlining inflates the HTML, is re-downloaded on every navigation in an SPA, and hurts repeat views. Keep it above-the-fold only.
10. Confirm the result: FCP improves, no new CLS appears from unstyled first paint, and the total transferred bytes did not increase overall.

## Patterns

Inline the critical block, then load the full sheet without blocking paint:
```html
<head>
  <meta charset="utf-8" />
  <link rel="stylesheet" href="/css/critical.css" media="print" onload="this.media='all'" />
  <noscript><link rel="stylesheet" href="/css/critical.css" /></noscript>
  <style>
    /* Generated by the build, never hand-edited */
    :root { --fg: #111827; --bg: #fff }
    body { margin: 0; color: var(--fg); background: var(--bg); font: 16px/1.5 "Inter Fallback", system-ui, sans-serif }
    .hero { display: grid; grid-template-columns: 1fr; gap: 1rem; padding: 2rem }
    @media (min-width: 64rem) { .hero { grid-template-columns: 1fr 1fr; padding: 4rem } }
  </style>
</head>
```

Build-time extraction and per-route CSS:
```js
// build/critical-css.mjs — run before the bundler, or as a post-build step
import { writeFile, readFile } from "node:fs/promises";
import { Beasties } from "beasties";

const beasties = new Beasties({
  path: "dist/index.html",
  publicPath: "/",
  preload: "swap",
  inlineFonts: false,
  reduceInlineStyles: false,
});

await beasties.process();
for (const view of ["index", "product", "checkout"]) {
  await beasties.process(`dist/${view}/index.html`);
}
console.info("inlined critical bytes:", (await readFile("dist/index.html", "utf8")).length);
await writeFile("dist/critical-report.json", JSON.stringify(beasties.critical));
```

```js
// postcss.config.mjs — fold @import into one file so there is no request chain
export default { plugins: { "postcss-import": {}, cssnano: { preset: "default" } } };
```

Defer off-screen work with CSS only, plus a route-level preload hint:
```css
/* Below-the-fold sections skip style/layout work during first paint */
.below-fold {
  content-visibility: auto;
  contain-intrinsic-size: auto 720px;
}
```

```html
<!-- Warm the stylesheet for the next route instead of blocking this one -->
<link rel="prefetch" href="/css/product.css" as="style" />
<!-- Chromium only; other browsers ignore it safely -->
<script type="speculationrules">
  { "prerender": [{ "where": { "href_matches": "/*/product/*" }, "eagerness": "moderate" }] }
</script>
```

## Checklist

- [ ] Baseline FCP/LCP recorded under throttling, with render-blocking resources listed.
- [ ] Critical CSS generated by a tool from a real render, not written by hand.
- [ ] Inlined block stays small (roughly 14KB compressed or less).
- [ ] Full stylesheet loads via `media="print"` swap with a `<noscript>` fallback.
- [ ] Zero `@import` rules remain in shipped CSS.
- [ ] CSS is split per route, not shipped in full on every page.
- [ ] CI regenerates the critical block and fails when the committed output differs.
- [ ] `content-visibility` used on long below-the-fold regions.

## Anti-patterns

**Inlining the entire stylesheet.** A 200KB inlined `<style>` block makes HTML the slowest resource on repeat views and cannot be cached independently of the markup. Fix: inline only what first paint needs; ship the rest as a deferred file.

**Critical CSS maintained by hand.** It silently diverges from the real stylesheet, so the first paint shows stale styles and the mismatch is invisible until a screenshot test catches it. Fix: generate it in the build and diff-check the output in CI.

**Hiding FOUC with `visibility: hidden` on `<html>`.** Text stays invisible until the stylesheet loads, which is slower than the flash it was meant to hide and blocks LCP entirely. Fix: inline enough critical CSS that the first paint is already correct.
